# Обработка сетевых ошибок в PyQt6

## Какие изменения внесены
Реализована защита от падения клиента при отключении сервера, настроено безопасное завершение потоков при закрытии окна, а также добавлен визуальный индикатор статуса соединения.

## Как обрабатывается потеря соединения
В класс `ReceiveThread` добавлен сигнал `disconnected = pyqtSignal()`. В методе `run()` чтение данных из сокета обернуто в `try/except`. Если происходит сбой сети (`OSError`) или сервер штатно закрывает соединение (`recv()` возвращает `None`), поток прерывает цикл и отправляет сигнал `disconnected`. 
В главном потоке интерфейса (`MainWindow`) этот сигнал перехватывается методом `on_disconnected`, который выводит сообщение `[Система] Соединение с сервером потеряно` и блокирует элементы ввода (`setEnabled(False)`).

## Как организована остановка SendThread
В класс `SendThread` добавлен метод `stop()`, который отправляет значение `None` в очередь (`self.queue.put(None)`). Так как в методе `run()` уже была заложена проверка на `None`, при получении этого значения бесконечный цикл прерывается, и поток корректно завершается. 
Для вызова остановки переопределен метод `closeEvent` главного окна: при нажатии на "крестик" программа сначала вызывает `self.send_thread.stop()`, а затем закрывает сокет для остановки зависшего `ReceiveThread`.

## Выполненные проверки
1. Проверка потери связи. При активном клиенте сервер был остановлен вручную. Клиент не закрылся с ошибкой, а корректно вывел системное сообщение и заблокировал ввод.
2. Проверка закрытия приложения. Окно клиента было закрыто крестиком во время работы. В консоли нет ошибок, процесс не зависает в фоне, потоки завершаются штатно.

## Индикатор состояния
В интерфейс `MainWindow` добавлен индикатор состояния сети. 
* По умолчанию метка `status_label` инициализируется с текстом `Connected to ...`.
* При срабатывании сигнала `disconnected`, метод-обработчик меняет текст метки на `Disconnected`. 
Индикатор успешно обновляется при обрыве связи в реальном времени.
